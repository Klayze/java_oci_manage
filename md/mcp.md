# MCP 接入

[English](./en/mcp.md)

让 Claude Code、Codex、Cursor 这类 AI agent 通过面板操作你授权的主机。

关键点是凭据不落到 agent 手里：SSH 密码和私钥始终留在面板，agent 拿到的只是一个令牌，能碰哪几台主机、能不能执行命令都由你签发时决定，随时可以撤销。

入口在顶栏设置 → 「MCP 接入」。需要闪电权益。

---

## 开始之前：证书

**Claude Code 和 Codex 不接受自签证书。** 面板默认用的就是自签证书，这种情况下 agent 连不上，而且报错信息通常看不出是证书问题。

两条路：

- 在「设置 → SSL 证书设置」里开启 ACME，签一张 Let's Encrypt 证书（需要一个域名，见 [Web SSH 终端指南 — SSL 证书配置](./webssh.md#ssl-证书配置)）
- 或者自己在前面挂一层反向代理，用已受信任的证书

MCP 页面检测到没启用 ACME 时会直接提示，别忽略那条提示。

## 签发令牌

点「新建令牌」，四个字段：

| 字段 | 说明 |
|------|------|
| **名称** | 自己认的标识，比如 `claude-code-laptop`。撤销时靠它区分 |
| **权限** | 只读或可执行，见下 |
| **有效期** | 到期自动失效 |
| **授权主机** | 从已保存的会话里勾选，没勾的主机这个令牌碰不到。会话列表为空时先去保存主机 |

权限两级：

| 级别 | 能做什么 |
|------|---------|
| **只读** | 列出主机、读取文件。不能执行命令 |
| **可执行** | 在上面基础上加执行命令和写文件，等同于该 SSH 账号的 shell 权限 |

生成后令牌**只显示这一次**，页面同时给出三份现成的配置片段：Claude Code、Codex CLI（`~/.codex/config.toml`）、Cursor 或其他客户端用的通用 JSON。复制对应的那份贴进客户端配置即可，不用自己拼端点地址。

## agent 能做什么

一期覆盖 SSH，六个工具：

| 工具 | 权限 | 作用 |
|------|------|------|
| `ssh_list_hosts` | 只读 | 列出这个令牌被授权的主机 |
| `ssh_read_file` | 只读 | 读取远端文件 |
| `ssh_exec` | 可执行 | 执行命令。55 秒内出结果就直接返回，超过则转后台任务并返回任务号 |
| `ssh_job_read` | 可执行 | 按任务号读后台任务的输出 |
| `ssh_job_cancel` | 可执行 | 取消后台任务 |
| `ssh_write_file` | 可执行 | 写远端文件，覆盖写时保留原文件权限 |

长时间运行的命令不会把 agent 卡住 —— 转成后台任务后，agent 可以先做别的，回头再按任务号取结果。

每次调用都会逐项核对：令牌有效且未撤销、权限级别够、目标主机在白名单里。主机指纹同样按面板里保存的记录校验，配了代理的主机如果代理不可用会直接拒绝，不会退回直连。

## 两条安全须知

页面上写了，这里再说一遍，因为这是最容易出事的地方。

**1. 给 agent 单独建一个没有 sudo 的账号。**

agent 能执行命令，就能在服务器上自己留后门。别把 root 或你日常用的账号交给它。建议：

```bash
# 服务器上建个专用账号，不给 sudo
useradd -m -s /bin/bash aiagent
```

再把这个账号的 `authorized_keys` 放到 root 所有的目录里，这样 agent 自己改不了它：

```
# /etc/ssh/sshd_config
AuthorizedKeysFile /etc/ssh/keys/%u
```

然后在面板里用这个账号保存主机，签令牌时只勾这台。

**2. 命令输出会作为上下文发给 AI 服务商。**

agent 读到什么，AI 服务商就看到什么。别让它去读私钥、配置文件里的密码、数据库导出这类东西。只读令牌也拦不住这个——只读限制的是"不能改"，不是"不能看"。

## 撤销和审计

令牌列表上每个令牌显示授权主机数、到期时间、最近使用时间。

点「撤销」立即生效：用它的 agent 当场失去访问权限，**它正在跑的后台任务也会被一并中止**。

下面的「调用记录」是完整的调用审计，包含签发、撤销、每次工具调用。记录可以刷新和清空。
