# 甲骨文开机教程

[English](./en/boot-oracle.md)

机器人端和 Web 端都能开机，用的是同一套后台队列和同一份配置，选顺手的即可。

- **Web 端** — 参数一屏填完，Shape 和镜像可以搜索着选，第一次开机建议用这个。
- **机器人端** — 手机上就能操作，适合在外面补开、批量开、多客户端同时开。

不管从哪端提交，任务都在客户端服务器后台跑，结果通过 Telegram 通知，不用守着页面。

---

## 开始之前

三样东西缺一不可：

1. 客户端已激活 — 见 [上手教程](./quickstart.md)
2. 甲骨文 API 配置已上传 — 见 [甲骨文云 API 配置](./oracle.md)
3. SSH 公钥或 Root 密码，至少选一个。两个都不给会直接被拦下来

公钥不用提前准备，开机表单里可以现场上传。

## Web 端开机

进「云管理 → 实例管理 → 创建实例」。表单分四块：基础配置、系统配置、网络与安全、高级选项。

### 最快的开法

点「快速配置」的两个按钮之一，大部分字段会自动填好：

| 按钮 | 预填内容 |
|------|---------|
| **AMD 微型 1C/1G** | 1 核 1G，Ubuntu 非 Minimal 镜像，硬盘默认，数量 1，延迟 1-2 秒，自动选中第一个公钥 |
| **ARM A1 2C/12G** | 2 核 12G，其余同上 |

租户里没有对应 Shape 时按钮会提示，不会静默失败。

填完检查一眼数量和公钥，点「开始创建」，弹窗里核对规格、系统、脚本，点「确认创建」。

提交后页面上会显示最终结果，Telegram 也会收到通知。

### 逐项填

| 字段 | 说明 |
|------|------|
| **规格** | 甲骨文的 Shape 名称，支持搜索。带 `A1` 的是 ARM，`E2`/`E3`/`E4` 是 AMD |
| **OCPU / 内存** | 弹性规格才可调，超出范围会当场报错 |
| **数量** | 一次开几台。从启动盘创建时强制为 1 |
| **镜像 / 启动盘** | 两个 tab。选「镜像」是全新装系统；选「启动盘」是拿现有的未附加启动盘直接开机，机器和数据都保留 |
| **操作系统** | 支持搜索。名字里带 Minimal 的是精简镜像，装完很多命令都没有 |
| **硬盘大小(GB)** | 留空走默认。免费额度总共 200GB，开多台要自己分配 |
| **SSH 公钥** | 从已存的公钥里选，或点「上传公钥」现场贴一个（要以 `ssh-` 开头） |
| **设置Root密码** | 打开后系统生成一个 root 密码，只在开机成功通知里出现一次，机器人不留存 |
| **公网IP** | 关掉就只有内网 IP |
| **传输加密** | 一般保持默认即可 |
| **延迟区间(秒)** | 抢机重试的间隔，填最小和最大值，实际间隔在区间内随机 |
| **启动脚本** | 开机后自动执行的 Shell 脚本，留空则不执行 |

### 从启动盘开机

机器被暂停或误删实例（保留了启动盘）时用这个：切到「启动盘」tab，选一块未附加的盘。

限制有两条：一次只能开一台；实例只能开在这块盘所在的可用域，跨 AD 会被甲骨文直接拒绝，任务会立刻终止并通知。

如果实例还在、只是盘掉了，不用重新开机 — 在「卷管理 → 未附加启动盘」面板里把盘直接附加回去更省事，前提是目标实例已停止。

### 快捷开机

下拉框里是在机器人端保存过的开机配置，选一个就能把整张表填满。没保存过会显示为空 — 这个配置只能在机器人端建。

## 机器人端开机

### 1. 打开键盘

发 `/oracle`，出现甲骨文操作键盘。多账号的先在「13. profile管理」里切到要用的 Profile，多客户端的在「14. 客户端管理」里切。

### 2. 点「1. 开机(刷ARM)」

按提示逐项设置，字段和 Web 端一一对应：CPU 类型 → CPU 数量 → 内存 → root 密码 → 公钥 → 硬盘 → 数量 → 地区 → 脚本 → 公网 IP → 传输加密。

CPU 类型要填甲骨文的内部 Shape 名称，键盘上有链接可以查，`aarch` 开头的是 ARM。

### 3. 二次确认

参数选完机器人会回一条汇总，**这时候还没开始**。核对无误后再点键盘上的确定开机按钮，任务才真正提交。

### 4. 批量开

「17. 快捷开机」可以先把一套参数存下来，之后：

- 多个配置 + 多个 Profile → 同一客户端上并行开
- 多个配置 + 多个客户端 → 多台客户端并行开

两者都选时，只有多客户端生效。

## 抢机是怎么回事

甲骨文的免费 ARM 长期缺货，开机大概率会提示 `Out of host capacity`（没货）。提交后客户端会一直替你重试，直到开出来或者你取消：

- 每次间隔在你设的延迟区间内
- 开出来一台就发一条 Telegram，带 IP、root 密码、试了多少次、花了多久
- 如果一直失败的原因是配额不够而不是没货，也会通知你，这种情况重试没用
- 正在跑的任务在机器人「21. 查看运行中的任务」或 Web 端任务列表里看，随时可以取消

抢机会持续跑很久，属正常现象。

### 强开 ARM

试用期账户专用，开机表单里的「试用期强开 ARM」开关。它能明显提高 ARM 的创建成功率，代价是过程中会短暂使用账户的收费功能。

界面上标了「高危功能，风险自担」，不是客套话，用之前想清楚。非试用期账户别开。

## 开不出来的常见原因

| 通知里的提示 | 原因和处理 |
|------|------|
| `Out of host capacity` | 缺货，没别的办法，让它继续抢。试用期账户可以考虑强开 ARM |
| 超出限额，无法开机 | 配额用完了。发 `/oracle` 点「20. 查询配额」看 ARM 核心、内存、硬盘各剩多少 |
| 硬盘超出限额 | 总硬盘超了 200GB。删掉不用的启动盘，或把新机器的盘调小 |
| 所有可用域均因超出限额而无法创建实例 | 同上，是配额不是缺货，一直重试也不会成功 |
| root开启和公钥必须选择一个 | 两个都没给，回去补一个 |
| 找不到你选择的镜像 | 镜像在当前区域下架了，重新选一个 |
| 跨 AD 报 400 后任务终止 | 从启动盘开机时选错了可用域，见上面「从启动盘开机」 |

已经超开的 A1 账号（甲骨文可能回收），可以用 Web 端的「A1 配置体检」批量降回免费额度，见 [常用操作教程](./howto.md#a1-免费额度体检)。

## 开完之后

- 开机成功通知里的 root 密码只出现一次，先存下来
- Web 端实例卡片上点「SSH」直接连，不用手填 IP
- 想换 IP、绑域名，见 [常用操作教程](./howto.md#换-ip-并自动更新-dns)
- 想让实例挂了自动拉起，机器人「10. 实例状态监控自启」或 Web 端设置里的监控自启
